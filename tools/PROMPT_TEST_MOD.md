# Промпт: большой тестовый мод для Cossacks 3 Modloader

> Как пользоваться: вставь текст ниже (от «Ты пишешь мод…») в нейросеть и приложи файлы из репозитория:
> **обязательно** `AI_MODDING_REFERENCE.md`; желательно `GAME_STATE.md` (типы и переменные игры) и
> `GAME_SCREENS.md` (экраны и кнопки). Ответ нейросети — готовые файлы мода: положить папку в
> `<игра>/modloader/mods/`, перезапустить игру, выполнить план проверки из README мода.

---

Ты пишешь мод для игры Cossacks 3 (RTS, XVII–XVIII век) под Cossacks 3 Modloader. Мод одновременно —
**настоящий интересный мод** и **большой тест модлоадера**: он должен задействовать почти все его
возможности, а сам мод — сообщать, что работает, а что нет.

## Жёсткие правила

1. Единственный источник правды — приложенный `AI_MODDING_REFERENCE.md`. Используй **только**
   функции, события, поля манифеста и форматы, которые там описаны. Ничего не выдумывай. Если чего-то
   нет — обойдись без этого или используй `native.<Имя>` / `game.exec` c кодом Pascal строго по правилам
   справочника, и явно пометь такие места комментарием `-- ПРЕДПОЛОЖЕНИЕ:`.
2. Поля и переменные игры (`TObj`, `TObjBase`, `gMap`, `gPlayer`...) — только из `GAME_STATE.md`, если он
   приложен. Без него — только то, что есть в примерах справочника.
3. **Не пиши патчи скриптов игры (`patches/*.patch`) и не заменяй файлы (`assets/`)** — у тебя нет текста
   файлов игры, патч наугад не встанет. Новое содержимое — только через `content.lua`.
4. Соблюдай стороны (client / server / shared) и таблицу доступности из справочника §3. Всё, что меняет
   мир в сетевой игре, — в `shared`. На `client` нет `game.exec`, `units.*`, `buildings.*`, `balance.*`.
5. Производительность: никаких `game.exec` / `state.*` / `units.*` в цикле по всем юнитам на каждом такте.
   Массовый обход — `objects.*`, и не чаще раза в секунду (считай такты в `game.tick`).
6. Каждый обработчик событий и каждую функцию, вызываемую по таймеру, оборачивай так, чтобы ошибка одной
   подсистемы не ломала остальные (`pcall` с записью в лог и в отчёт самопроверки).
7. Все сообщения в лог — с префиксом подсистемы: `log.info("[veteran] ...")`.
8. Код — Lua 5.4, чистый и прокомментированный по-русски: коротко, зачем, а не что.

## Идея мода: «Гетьманщина: слава и ветераны»

### 1. Новая нация и юниты — `content.lua`
- Нация **Гетьманщина** (`sid = "het"`, шаблон — Украина `ukr`), названия ru / uk / en.
  Убери у неё одного юнита шаблона через `remove` (выбери по смыслу из юнитов, которые знаешь из
  справочника; если не уверен в sid — не убирай ничего и напиши об этом в README).
  Стартовая прибавка ресурсов: немного еды и золота.
- Два новых типа юнитов для `het` (и один из них — ещё и для `ukr`):
  - **Реестровый казак** — от `serdiuk`, больше здоровья, дороже (`price[...]`);
  - **Гетманская гвардия** — от родителя на твой выбор из известных по справочнику (`serdiuk`,
    `musketeer`, `pikeman`, `archer`, `tatar`...), свои `base`, своя клетка `cell`, названия и описания.

### 2. Ветераны — `shared`
- Считай убийства каждого юнита: по `unit.damage` запоминай последнего атакующего цели, по
  `unit.death` засчитывай убийство ему.
- Звания: 3 убийства — «ветеран», 7 — «элита». При повышении — прибавка здоровья юниту
  (через `state.set("obj(h).hp", ...)` в `shared`, не выше максимума типа) и сообщение в лог.
- Таблица «героев» (топ-5 по убийствам) — хранится в `shared`, сбрасывается в `game.start`.
- Убитый/исчезнувший юнит (`unit.destroy`) — убрать из таблиц, чтобы не копились хендлы.

### 3. Военный совет — `server` + `client` + сеть
- Клиент по клавише **F7** просит у сервера «военный налог» (`net.send`).
- Сервер определяет игрока через `game.playerIndexOf(from)`, проверяет перезарядку (не чаще раза в
  5 минут игрового времени на игрока, считай по `game.tick`), выдаёт золото `player(i):add` и сообщает
  всем `net.broadcast`. Отказ (перезарядка) — тоже сообщением, с оставшимся временем.
- Данные от клиента не доверять: сумму решает сервер.

### 4. Интерфейс — `client` + страница CEF
- HUD-страница `web/hud.html`, режим `web.passthrough(true)`, прозрачный фон, открывается в
  `game.start`, закрывается в `game.end`, **F9 не использовать** (занята), переключение показа — **Ctrl+H**.
- На HUD: выбранное здание (`buildings.selected` / `buildings.info` через `game.api`) — имя, здоровье,
  очередь; число своих юнитов по типам (считать в Lua клиента через `objects` раз в секунду и
  передавать странице через `web.eval`); таблица героев и звания (сервер/`shared` рассылает её клиентам
  через `net.broadcast` раз в несколько секунд, клиент передаёт в страницу).
- Страница ждёт `window.game` перед первым вызовом, все вызовы `game.api` — с `try/catch`.
- Замена кнопки главного меню: по кнопке «Settings» главного меню — сначала сообщение в лог, потом
  родное поведение (не блокировать).

### 5. Приказы
- `player.order`: не давать игроку атаковать собственные здания и юнитов (если цель — свой объект,
  `return true` и сообщение в лог). Как узнать владельца цели — только способами из справочника
  (`objects.read(h).pl` и индекс своего игрока `native.GetPlayerIndexInterfaceIO()`).
- `unit.order` (в `shared`): вести статистику приказов по типам для самопроверки, ничего не отменять.

### 6. Графика — `client`
- По **Ctrl+G** — переключение «кинематографичного» профиля графики `gfx.apply` и обратно
  (снимок `gfx.snapshot()` перед первым переключением).

### 7. Самопроверка (самое важное для теста)
- По **Ctrl+T** — отчёт в лог, строки вида `[selftest] PASS/FAIL/SKIP <проверка> — <детали>`.
  Занятые клавиши, которые брать нельзя: F9, F10, F12, Insert, End.
- Проверки (каждая в `pcall`, провал одной не останавливает остальные):
  1. события: сработали ли `game.start`, `game.tick`, `unit.spawn`, `unit.death`, `unit.damage`,
     `unit.order`, `player.order`, `building.spawn` (счётчики с начала партии);
  2. `objects.status()` = "fast"; время чтения всех объектов `objects.read` (мс);
  3. `balance.get` нового юнита «реестровый казак» совпадает с `base` из `content.lua`;
  4. `units.selected()` работает (на стороне, где он доступен);
  5. сеть: запрос налога дошёл до сервера и ответ вернулся (флаги);
  6. HUD: страница открыта (`web.isOpen()`), ответ страницы пришёл (страница вызывает
     `game.api` своей проверочной функции — если такой механизм описан в справочнике; иначе SKIP);
  7. `state.get("gMap.gamestage")` читается;
  8. ветераны: хотя бы одно убийство засчитано (иначе SKIP с подсказкой «повоюйте»).
- В конце — итог: `N PASS, M FAIL, K SKIP`. Тот же отчёт автоматически в `game.end`.
- Так как сторон несколько, у каждой стороны свой раздел отчёта (`[selftest:client]`, `[selftest:shared]`...).

## Что выдать

1. Дерево файлов мода.
2. **Полное** содержимое каждого файла (без «...» и «остальное аналогично»):
   `manifest.lua`, `content.lua`, `shared.lua` (или `server.lua` — объясни выбор), `client.lua`,
   модули через `files` + `require` (раздели код по подсистемам: `veterans.lua`, `council.lua`,
   `selftest.lua`...), `web/hud.html`, `README.md`.
3. `README.md` мода:
   - что делает мод и какие клавиши;
   - **план ручной проверки** по шагам: что сделать в игре и что должно получиться
     (включая выбор нации «Гетьманщина», найм новых юнитов, бой для ветеранов, F7, Ctrl+H, Ctrl+G, Ctrl+T);
   - список всех мест `-- ПРЕДПОЛОЖЕНИЕ:` — что ты не смог подтвердить по справочнику;
   - какие возможности модлоадера мод НЕ проверяет и почему.
4. `id` мода: `hetmanate_test`, `multiplayer = "required"` (мод меняет правила).

Перед ответом перечитай справочник и проверь каждый вызов: существует ли функция, на правильной ли она
стороне, правильные ли аргументы события. Лучше меньше возможностей, но всё рабочее.
