# HANDOFF — что нужно знать, прежде чем менять модлоадер

Для разработчика или нейросети, которая продолжает проект. Подробности: `DOCUMENTATION.md` (устройство),
`AI_MODDING_REFERENCE.md` (Lua API), `MODEL_FORMATS.md` (модели), `GAME_API.md` / `GAME_STATE.md` (игра).

## Инварианты — не ломать

1. **Lockstep.** В сетевой игре каждый компьютер считает партию сам. Всё, что меняет мир, должно
   выполняться одинаково у всех (`shared`), иначе тихий рассинхрон. `server` — только у хоста.
   Случайность для shared — от зерна карты (`gMap.settings.gen.randkey0/1`), не `RandomExt`.
2. **Checksum лобби.** Игра сравнивает MD5 всех скриптов. Любая строка, которую модлоадер вставляет
   в скрипты игры, должна содержать `ML:` — такие строки вычёркиваются из хеша (`core/Checksum.cpp`).
   Иначе с модлоадером не пустит в сетевые комнаты с чистой игрой.
3. **Файлы игры не трогаем.** Замена — `assets/`, правка скриптов — `patches/*.patch` (ScriptPatch),
   генерация — `content.lua`. Всё собирается в `modloader/cache` при запуске через хук файлового слоя
   движка. Поэтому игра запускается только через `Cossacks3Launcher.exe` (внедрение до старта).
4. **Одна страница CEF на все моды.** HUD обязан проверять `web.url()`, прежде чем рисовать.
5. **Поток игры.** Скрипты, рендер и CEF — в главном потоке игры. Код Pascal исполнять только через
   `ScriptRunner` (очередь главного потока), не из своих потоков.
6. **Хендлы объектов отрицательные.** Поля `Byte/Word` в схеме имеют `bytes=1/2` — без этого
   калибровка `objects` ломается.
7. **Клиент только читает.** На клиенте нет `game.exec`; нативы для клиента — белый список (Get/Is/...).

## Ключевые места в коде

| что | где |
|---|---|
| адреса и сигнатуры движка | `core/GameApi.h`, `core/NativesTable.inc` |
| вызов нативов из C++ | `core/NativeCall.cpp` (проверяет число аргументов, восстанавливает ESP) |
| исполнение Pascal | `core/ScriptRunner.cpp` |
| события (вставки `ML:` в состояния игры) | `core/Events.cpp`, `core/Game.cpp` |
| замена файлов, кеш, патчи | `core/Assets.cpp`, `core/ScriptPatch.cpp` |
| нации, юниты, битвы, локализация | `core/Content.cpp` |
| Lua, моды, API | `core/LuaHost.cpp`, `api/*.lua` |
| сеть модов, проверка модов в комнате | `core/Net.cpp` (пакет 7700), `core/ModCheck.cpp` |
| встроенные компоненты на Lua | `builtin/` (детектор рассинхронов) |

## Проверено в игре / ждёт проверки (на 2026-09-23)

Проверено: события, Lua, сеть на 2 ПК, замена файлов и патчи, новые юниты и нации (zap, mon, het),
загрузка .oss, HUD, быстрый `objects` (1424 юнита за 46 мс), `model{}` в content.lua: .glb -> .osm + DXT5 .dds
(куб вместо ukrcen, 2026-09-24; несжатую DDS движок не рисует — кадры молча пропускаются).

Ждёт проверки:
- `desync_watchdog` в сетевой партии: снимки делаются в событии `net.sync` (вставка в состояние
  `ReadLanSyncData` библиотеки progress.aix — команда lockstep, её все выполняют на одном шаге);
- savedata, битва из `battle{}`, `remove`/`resources` в `content.lua`;
- checksum с выключенными модами = `3E5A91861D0C4F933996B8FC2F75E7EB`.

Известные проблемы:
- патчи `content.lua` ищут строки-якоря в скриптах игры; после обновления игры могут молча не лечь;
- здания новых наций теперь получают точки из `objcustom.cfg` (исправление ошибки `resourcepoint on collision` у `zapcen`) — не проверено в игре.

## Сборка и выпуск

```
MSBuild "Modloader For Cossacks 3.slnx" /p:Configuration=Release /p:Platform=x86
python tools/make_release.py <версия>      # dist/Cossacks3Modloader-<версия>.zip
```
Собирать именно `.slnx` (отдельный vcxproj не находит CEF). Режим разработчика — файл
`<игра>/modloader/dev.txt`: F9 ресурсы (одиночка), End выгрузка, F12 DevTools, `.reload` в консоли.
