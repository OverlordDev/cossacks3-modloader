# Cossacks 3 Modloader — документация

Модлоадер для Cossacks 3 (Steam, сборка 2.2.3): встраивается в игру при запуске и даёт модам Lua,
события игры, HTML-интерфейсы (CEF), замену файлов и правку скриптов игры, проверку модов в сети.
Файлы игры не меняются — всё происходит в памяти процесса.

Документы:

| документ | для кого |
|---|---|
| `DOCUMENTATION.md` (этот) | как модлоадер устроен, установка, сборка, все подсистемы, ограничения |
| `MODDING.md` | быстрый старт для мододела |
| `AI_MODDING_REFERENCE.md` | полный справочник API для нейросети, которая пишет моды |
| `api/README.md` и заголовки `api/*.lua` | подробности по каждому модулю Lua |
| `GAME_STATE.md` | все глобальные переменные и типы (записи) скриптов игры |
| `GAME_SCREENS.md` | экраны игры, их состояния и кнопки |
| `GAME_API.md` | 4856 нативных функций движка |

## 1. Из чего состоит

```
<игра>/
  Cossacks3Launcher.exe     запуск игры с модлоадером (заставка, внедрение до старта)
  Cossacks3Loader.dll       маленький загрузчик: копирует и грузит основную DLL, умеет перезагружать её
  Modloader For Cossacks 3.dll   основная DLL (core): хуки, Lua, CEF, события
  Cossacks3Cef.exe          дочерний процесс Chromium (рендер страниц)
  cef/                      файлы CEF (ставятся tools/install_cef.py)
  modloader/
    api/                    Lua-библиотека поверх игры (state, units, buildings, objects...)
    mods/<мод>/             моды
    web/                    общие файлы страниц
    cache/                  файлы игры, собранные с патчами модов (пересоздаётся при запуске)
    crashes/                отчёты о сбоях и минидампы
    modloader.log           лог (пишется всегда)
    modstate.txt            какие моды включены (меню Insert)
    dev.txt                 если файл есть — режим разработчика
```

Исходники (этот репозиторий):

| папка | что |
|---|---|
| `Modloader For Cossacks 3/core/` | основная DLL, C++ |
| `Launcher/`, `Loader/` | запуск и загрузчик |
| `CefSub/`, `CefWrapper/` | процесс CEF и обёртка libcef |
| `api/` | Lua-библиотека (копируется в `<игра>/modloader/api`) |
| `examples/mods/` | примеры модов |
| `tools/` | генераторы справочников (IDA, скрипты игры), тесты api |
| `external/` | lua, imgui, minhook, cef |

## 2. Установка и запуск

1. Собрать решение `Modloader For Cossacks 3.slnx` (Release, x86 — игра 32-битная).
2. Скопировать в папку игры: `Cossacks3Launcher.exe`, `Cossacks3Loader.dll`,
   `Modloader For Cossacks 3.dll` (+ `.pdb` — для имён функций в отчётах о сбоях), `Cossacks3Cef.exe`.
3. `python tools/install_cef.py` — поставить CEF в `<игра>/cef`.
4. Скопировать `api/` в `<игра>/modloader/api/`, моды — в `<игра>/modloader/mods/`.
5. Запускать через `Cossacks3Launcher.exe`.

Launcher создаёт процесс игры приостановленным, внедряет загрузчик и только потом пускает игру.
Поэтому хуки стоят раньше, чем игра прочитала первый файл: без этого не работали бы замена файлов,
патчи скриптов и шейдеры.

Сборка из командной строки:

```bash
MSBuild "Modloader For Cossacks 3.slnx" -t:"Modloader For Cossacks 3" -p:Configuration=Release -p:Platform=x86
```

## 3. Жизненный цикл

1. **Загрузчик** (`Cossacks3Loader.dll`) копирует основную DLL во временную папку и грузит копию —
   так DLL можно пересобрать и перезагрузить командой `.reload`, не закрывая игру (пока не запущен CEF).
2. **Ранние хуки** (сразу, до старта игры): обработчик сбоев, SwapBuffers (кадр), контрольная сумма
   скриптов, файловый слой (замена файлов и патчи), логгеры движка.
3. **Движок поднялся** (первый вызов скрипта): трамплин событий, вставки в состояния GUI и библиотек
   юнитов/зданий, загрузка Lua-модов, оверлей (ImGui), затем CEF.
4. **Каждый кадр**: очередь скриптов, события игры, отрисовка страницы CEF и меню Insert.
5. **Выход**: хуки снимаются, CEF закрывается, лог дописывается.

## 4. Подсистемы

### 4.1. Вызов кода игры (ScriptRunner)

Скрипты игры — Pascal (движок TXDMScript). Модлоадер добавляет строки кода в служебное состояние
GUI и выполняет его — так работают `game.exec`, `game.eval`, консоль, большая часть api.
Синхронный вызов возвращает строку через `ML_RET(...)`, аргумент передаётся как `ML_ARG`.
Каждый вызов компилируется (порядка миллисекунды), поэтому для массового чтения объектов есть
`objects` (4.8).

Нативные функции движка (4856 штук) вызываются напрямую из C++ (`native.<Имя>` в Lua): аргументы
раскладываются по соглашению `__stdcall`, `var`-параметры возвращаются из Lua лишними значениями.

### 4.2. События (Events)

Движок не даёт событий — модлоадер вставляет в код состояний строку
`DScriptSetgDbgString0('ML:<событие>|<данные>')`. Этот натив игра не использует — его вызов
перехвачен и превращён в событие для Lua. Ответ обработчика («отменить») возвращается в ту же
строку, и вставка проверяет его (`if DScriptGetgDbgString0='ML:block' then exit`).

Где стоят вставки:

| событие | где |
|---|---|
| `game.*` | состояния GUI `DoNewGame`, `DoCreate`, `DoProgress`, `DoDestroy` |
| `unit.spawn/death/destroy`, `building.*` | библиотеки состояний `units\unit.aix`, `units\building.aix` (`Initial`, `OnDeath`, `OnDestroy`) |
| `unit.damage` | начало функции `_misc_DoDamage` (патч `lib\miscext2.script`) — весь урон |
| `unit.order` | начало функции `_unit_AddOrder` (патч `lib\unit.script`) — все приказы |
| `player.order` | вызовы `_player_OrderUnitsTo*`, `_player_SetGroupPosition` в `OnMouseDown` интерфейса |
| `net.*` | `OnLanEvent` |
| `guistate.*`, `guiscreen.*`, `ui.press` | состояния экранов, которые перехватили моды |

Вставки восстанавливаются сами, если игра перезагрузила скрипты. Строка, которая не компилируется
обёрнутой, остаётся как есть (запоминается, повторных попыток нет). Если патч библиотеки не
применился, `unit.damage` откатывается на обёртки вызовов в состояниях юнитов и снарядов.

### 4.3. Контрольная сумма и онлайн (Checksum)

Лобби и публичный сервер сверяют MD5 всех скриптов. Модлоадер перехватывает её подсчёт и считает
по исходному тексту: строки с `'ML:'` выкидываются, обёрнутые строки заменяются исходными
(`{ML:orig=...}`). Поэтому с модлоадером можно заходить в онлайн к игрокам без него.
Команда `.checksum` показывает хеш движка, хеш «чистой» игры и что лежит в служебной строке движка.
Моды с заменой или патчами скриптов меняют правила — с ними играть можно только с теми, у кого они
тоже стоят (это проверяет ModCheck).

### 4.4. Файловый слой: замена файлов и патчи (Assets, ScriptPatch)

Все файлы движок открывает через три функции (`CreateFileStream` 0x4C32FC, `CreateFileZipStream`
0x4C3460, `FileStreamExists` 0x4C3618). Через них же работают моды Steam Workshop (`<игра>/mods`).
Модлоадер перехватывает их и подменяет путь:

- `mods/<мод>/assets/<путь в игре>` — файл целиком вместо игрового;
- `mods/<мод>/patches/<путь в игре>.patch` — правки текстового файла по кускам (формат — `MODDING.md` §6).

Файл с патчами собирается при первом чтении движком: база (замена из assets → файл включённого
Workshop-мода → файл игры) + встроенные вставки модлоадера + патчи модов по порядку. Результат
пишется в `modloader/cache/<путь>` и отдаётся движку. Порядок модов — `priority` из манифеста, при
равном — имя папки; позже — главнее.

Файлы читаются на старте (скрипты, шейдеры) или при загрузке карты — после правки нужен перезапуск.
Новые файлы, которых нет в игре, не видны, если игра сама перебирает папку (перечисление каталогов
пока не перехвачено).

### 4.5. Lua (LuaHost)

Lua 5.4. У каждого мода своё окружение на каждую сторону:

| сторона | где работает | может |
|---|---|---|
| `client` | у каждого игрока | интерфейс, клавиши, страницы, чтение состояния, `net.send` |
| `server` | одиночная игра и хост | всё: `game.exec`, менять мир, ресурсы, `net.broadcast` |
| `shared` | у всех одинаково | как server, но выполняется на каждой машине — для правок мира в сети |

На клиенте нативы, которые меняют игру, запрещены (разрешены `Get*`, `Is*`, `Can*`, чтение GUI...).
Ошибка в моде пишется в лог с именем мода и стеком и не роняет игру. `.lua reload` — перезагрузить
все моды. Моды грузятся по `priority`, зависимости (`requires`) — раньше зависящих.

Сеть модов: `net.send` (клиент → хост) и `net.broadcast` (хост → все) идут пакетами игры,
данные — любые таблицы Lua. Хост определяет отправителя сам (`game.playerIndexOf(from)`).

### 4.5.1. Способности по координатам (`abilities`)

Модуль `abilities` предназначен для авиаударов, баллистики, миномётов и других ударов по
мировой точке. Он работает на `server`/`shared`, использует штатный `_misc_DoDamage` и
показывает игровой эффект взрыва: `cannon`, `howitzer`, `grenade` или `none`.

```lua
-- server.lua
abilities.define("airstrike", {
    cooldown = 20, damage = 100000, radius = 10,
    target = "all", effect = "cannon", ignorePeace = true,
})

net.on("airstrike.request", function(data, from)
    local p = game.playerIndexOf(from)
    local ok, hit, wait = abilities.fire("airstrike", data.x, data.z, { owner = p })
    net.broadcast("airstrike.result", { ok = ok, hit = hit, wait = wait })
end)
```

Клиент передаёт координаты прямо под курсором — выбор юнита не нужен:

```lua
input.bind("F6", function()
    local x, _, z = native.GetCurrentMouseWorldCoord()
    if x then net.send("airstrike.request", { x = x, z = z }) end
end)
```

`hit` — количество объектов в радиусе, а не количество убитых объектов. `ignorePeace` позволяет
способности работать во время мирного периода; включайте его только намеренно.

### 4.6. Интерфейс: страницы CEF (WebUi) и оверлей

- Chromium (CEF) рисует страницу в текстуру, модлоадер выводит её поверх игры. Страница мода — `web/*.html`.
- `window.game` в JS: `game.api(имя, ...)` — вызвать функцию api (ответ — объект),
  `game.tag(состояние, тэг)` — нажать родную кнопку, `game.exec(состояние)`, `game.lua(код)`, `game.close()`.
- Режим HUD (`web.passthrough(true)`): прозрачные места страницы пропускают мышь в игру, клавиатура
  идёт в игру, пока в странице не выбрано поле ввода.
- Экраны игры можно заменить своей страницей (`screens.replace`), кнопки — перехватить.
- Экран загрузки держится до `gMap.gamestage >= 2`; окно и OpenGL-контекст, которые игра пересоздаёт
  при загрузке, отслеживаются.
- Dev: F12 — DevTools, страницы перезагружаются при сохранении файлов.
- Меню **Insert** (ImGui): моды, включение/выключение, графика, состояние модлоадера.

Особенности, найденные на практике: CEF работает в потоке игры и не должен забирать ввод игры
(прокачка пропускается, пока в очереди есть ввод); фокус клавиатуры у главной формы игры, не у окна
рендера; окно браузера живёт в собственном скрытом окне — окна игры пересоздаются.

### 4.5a. Utility Libraries (api/60–70, чистый Lua)

Стандартный слой без C++: `mathx/vec/tablex/stringx/geometry/validate/color` —
чистые функции (shared-безопасны); `scheduler` (таймеры на game.tick, время
`GetGameTime`), `query` (`O(n)` сканы записями, building — один batched exec),
`rng` (splitmix64, `seedFromGame/sharedSeed`, число вызовов обязано совпадать
у всех игроков), `config` (savedata через `config.link`, dirty+save, версии+
migrate). Загрузка — автоматически по порядку имён (`validate`/`mathx` раньше
потребителей не обязательны: связи только на момент вызова). Тесты:
`tools/api_test/util_{pure,sim,world}.lua`, отчёт `utility tests: p/t`.

### 4.6a. Steam Rich Presence (SteamPresence, client-only)

Мост к уже загруженной игре `steam_api.dll` (`core/SteamPresence.cpp`):
статус Steam локального игрока — меню, лобби, партия (карта, режим, соперники).
Правила: НЕ вызываем `SteamAPI_Init/Shutdown`, `SteamwrapFree/APPUnload`;
только `GetModuleHandleW` (без `LoadLibrary`); `ISteamFriends` — только прямым
`CreateInterface("SteamFriends017/016/015")` с однократным тихим пробником
(версионированных `SteamAPI_SteamFriends_vXXX` в сборке нет — проверено dumpbin,
а маршрут через `ISteamClient` + pipe игры падает в steamclient — проверено
крашем 2026-09-26 и удалён; первый сбой = вечное отключение моста);
все вызовы только из главного потока игры (чужие — в очередь
`ScriptRunner::RunOnGameThread`), каждый вызов Steam — под `CrashHandler::Guard` + SEH.
Строки UTF-8 без перекодировки. Без Steam — `false`/`"Steam unavailable"`, игра
не падает. Lua: таблица `steam` только в client-окружении
(`available/status/set/clear/playedWith/myId`); автостатусы —
`builtin/steam_presence` (события `game.menu/prepare/start/end`), ручной API —
`api/58_steam.lua` (лимиты, троттлинг 3 с, дедуп). Очистка — на `game.end`,
выходе в меню и выгрузке (`LuaHost::Close` → `SteamPresence::Shutdown`).
Важно: ОТОБРАЖЕНИЕ текста зависит от настройки Rich Presence приложения
Cossacks 3 в Steamworks; ключи/значения пишутся и читаются всегда.
SteamID соперников движок не отдаёт — только ники + ручной `playedWith`.

### 4.7. Проверка модов в сети (ModCheck)

Хост с модлоадером опрашивает входящих игроков пакетом модлоадера, сверяет отпечатки модов
`multiplayer = "required"` (у которых есть server/shared часть, assets или patches) и кикает тех,
у кого мода нет или он другой. Отпечаток — FNV-1a по файлам мода (кроме `web/`), без учёта CR.
Клиентские моды (`optional`) не сверяются. `.modcheck` — состояние. В реальной сети ещё не проверено.

### 4.8. Быстрый доступ к объектам (objects, mem)

`mem.i32/u8/f32/str...` читают память игры с защитой (неверный адрес — `nil`, не падение).
`objects` находит данные юнита (как `_unit_GetTObj`: состояние объекта → аргумент 0) и считает
смещения полей TObj по схеме игры. Движок кладёт поля подряд без выравнивания; размеры Float/Boolean
и выравнивание записей модлоадер подбирает сам, сверяя память с ответом Pascal на трёх объектах при
первом обращении в партии. Не совпало — функции работают через Pascal, в логе предупреждение.

### 4.9. Сбои (CrashHandler)

Любое исключение даёт отчёт в `modloader/crashes/`: тип и объяснение, адрес, стек с именами
(модлоадер — из .pdb, игра — из таблицы функций IDA), регистры, чем модлоадер был занят (стек
областей: какой мод, какое событие), последние 60 строк лога, список модов, состояние CEF, модули.
Первые три — с минидампом. `.crashtest` — проверить.

### 4.10. Режим разработчика и консоль

`modloader/dev.txt` включает подробный лог (`[DEV]`), диагностику, DevTools и автоперезагрузку
страниц. Лог `modloader/modloader.log` пишется всегда — его и присылать при ошибках.

Консоль (окно рядом с игрой): строка — код Pascal игры; `=` — Lua (`=show(units.selected())`);
`? выражение` / `?i` `?f` `?b` — вывести; `/текст` — команда чата игры (`/res all 5000`).
Команды: `.help`, `.mods`, `.lua reload`, `.events`, `.checksum`, `.modcheck`, `.assets`,
`.find слова` (нативы и библиотека скриптов), `.state Имя`, `.hook Имя`, `.fps`, `.prof` (профилировщик),
`.web`, `.crashtest`, `.reload`, `.unload`.

## 7. Известные ограничения

- Моды с логикой в сети должны быть одинаковыми у всех (`shared`, `required`) — детектора рассинхрона нет.
- `unit.order` можно отменять в сети только одинаково на всех машинах.
- Нет перехвата перечисления папок — новые карты и файлы, которых нет в игре, игра не видит.
- Данные модов не сохраняются в сохранения игры.
- Шейдеры и часть ресурсов читаются один раз при старте — после замены нужен перезапуск.
- ModCheck и неизменность контрольной суммы с патчами библиотек ещё не проверены в реальной сети.
- CEF работает в потоке игры: тяжёлая страница замедляет игру.
