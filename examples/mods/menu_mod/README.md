# menu_mod — своё главное меню

`client.lua` перехватывает состояния интерфейса игры (`ShowMainMenu`, `ShowNews`) и рисует экран сам.
Нажатия уходят в родной `EventMainMenu` по тэгу, поэтому кампания, мультиплеер, настройки и выход
работают без переписывания логики.

## Свои картинки

Картинки интерфейса — это BMP в `data/hud/textures/ui/`, собранные в материалы через `data/hud/hud.mat`
(координаты куска текстуры) и `data/hud/hud.tex` (путь к файлу). Чтобы заменить картинку, достаточно
положить свой BMP с тем же именем в `assets/` — модлоадер подменит файл на лету, игра ничего не заметит.

| Что | Файл мода | Размер | Формат |
|---|---|---|---|
| Иллюстрация главного меню | `assets/data/hud/textures/ui/mainmenu_art.bmp` | 2048x1024 | BMP, 24 бита |
| Логотип | `assets/data/hud/textures/ui/logo_small.bmp` | 512x256 | BMP, 32 бита (с альфой) |
| Экраны загрузки, 8 штук | `assets/data/hud/textures/ui/progressbar1.bmp` … `progressbar8.bmp` | 2048x1024 | BMP, 24 бита |

Собрать BMP из своей картинки — `tools/make_menu_art.py`. Что делать, он понимает по имени целевого
файла: фон и экраны загрузки заполняет с обрезкой по краям, логотип вписывает целиком с прозрачными
полями и пишет 32 бита с альфой.

```bash
python tools/make_menu_art.py my.jpg examples/mods/menu_mod/assets/data/hud/textures/ui/mainmenu_art.bmp
```

```bash
python tools/make_menu_art.py my_logo.png examples/mods/menu_mod/assets/data/hud/textures/ui/logo_small.bmp
```

Логотип берите из PNG с прозрачностью: 32-битный BMP игры Pillow читает без альфа-канала, так что
исходником он не годится — прозрачность потеряется.

Важные мелочи:

- **Размер менять нельзя** без правки `hud.mat`. Движок берёт из текстуры прямоугольник, заданный там:
  у `mainmenu_art` это `CoordW=1674, CoordH=1024` внутри картинки 2048x1024 — то есть справа 374 пикселя
  текстуры не используются. У `logo_small` — 468x193 внутри 512x256. Рисуйте в тех же границах.
- **Без RLE-сжатия**, обычный BMP. Альфа-канал только там, где он был у оригинала (32 бита).
- Текстуры игра читает **один раз при запуске**, поэтому нужен запуск через `Cossacks3Launcher.exe`.
  При инжекте в уже идущую игру подмена не сработает.
- Проверить, что подмена подхватилась, — команда `.assets` в консоли модлоадера.

## Свои картинки отдельными файлами, без атласов

Проверено в игре: работает и то, и другое.

Почти все материалы игры вырезают прямоугольник из большого атласа (`tex05.bmp` — кнопки и рамки,
`dialogs01.bmp` — окна, `icons.bmp` — иконки), и размер такого куска зашит в `hud.mat`. Но материал
может ссылаться и на отдельный файл целиком — так в игре сделаны `misc.blank` и `loaddummy`.
`tools/make_materials.py` пользуется этим: берёт `hud.mat` игры, дописывает в конец секции под
картинки мода и кладёт результат в `assets/`. Атласы не трогаются, размер картинки любой.

```bash
python tools/make_materials.py "C:/.../Cossacks 3" examples/mods/menu_mod
```

Куда класть картинки (`.tga`, `.bmp`, `.dds`, `.jpg`, `.png`):

| файл | что получится |
|---|---|
| `assets/data/hud/textures/mods/menu_mod/btn.tga` | новый материал `menu_mod.btn` |
| `.../menu_mod/btn.normal.tga`, `btn.hover.tga`, `btn.pressed.tga` | набор состояний кнопки |
| `.../menu_mod/override/btn.medium.normal.tga` | **подменяет** родной материал игры |

Имя файла = имя материала. Кнопке достаточно одного материала без состояний: если `<имя>.normal`
не найден, игра берёт `<имя>` на все состояния (`_gui_CreateButton` в `data/scripts/lib/gui.script`).

Подпапка `override/` заменяет картинку игры на свою, и размер тоже любой — движок растянет материал
по размеру элемента. Осторожно: один материал часто используется в десятке мест сразу. Подмена
`btn.medium.normal`, например, меняет вид не только кнопок, но и строк списков в диалогах.

После добавления или удаления файлов скрипт надо перезапустить. После патча игры — тоже:
сгенерированный `hud.mat` это копия файла игры с нашим хвостом.

### Какой экран загрузки показывается

Игра выбирает его один раз за сессию: `gint_gui_progressbar_picnum := Floor(1+8*random)` в
`data/gui/menu.inc/docreate.inc`. Дальше имя складывается как `load.game.<высота>.<номер>`, где высота —
768, 900, 1024 или 2160 в зависимости от разрешения, а конфиги лежат в `data/hud/progressbar/`.
Каждый конфиг ссылается на материал `progressbar<номер>`, то есть все разрешения берут **одни и те же
восемь текстур** — заменить надо только восемь BMP, конфиги трогать не нужно.

Если хочется всегда один и тот же экран загрузки — это уже не картинка, а скрипт: перехватить
`DoCreate` и выставить свой `SetGUILoadProgressBarActiveName('load.game.1024.3')`.
