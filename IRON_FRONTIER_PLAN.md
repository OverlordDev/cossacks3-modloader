# План мода: «ЖЕЛЕЗНЫЙ ФРОНТИР» ( nineteenth century )

Мод на 19 век для Cossacks 3 через modloader 0.2.0. Документ — план, до кода ещё не приступаем.

---

## 0. Сначала — честные ограничения

Это влияет на всё остальное, поэтому читать до плана.

| Ограничение | Следствие |
|---|---|
| **Нельзя сделать новые 3D-модели и текстуры.** Модлоадер не умеет их генерировать | Новые юниты = **новые игровые сущности на существующих моделях**. Ровно так делает `examples/mods/new_unit_test`: `.prop` ссылается на `refunit.prop`, меш берётся чужой. Визуально это остаётся XVIII век — правится геймплей, баланс, роли |
| **`orders` и `weapon` не работают** (баг C++, `CPP_FIX_REPORT.md`) | Приказы движения/атаки и выстрел оружия недоступны. Артиллерию придётся строить на обходных путях — см. §4 |
| **Lockstep.** Мир меняет только shared/server, случайность только `rng.sharedSeed` | Вся игровая логика — в `shared.lua`. Клиент отвечает только за UI, камеру, звук, эффекты |
| **Нельзя запустить игру без вас** | Каждый этап проверяется вашим прогоном. Я делаю код и офлайн-тесты, вы — запуск |
| Своих звуков и музыки не сделать | Переиспользуем штатные библиотеки |

Вывод: мод будет **огромным по функционалу и системам**, а не по ассет-паку. Это честная формулировка, и я не буду делать вид иначе.

## 1. Концепция

**«Железный Фронтир»** — 1812–1815, Наполеоновские войны.

Не тотальная конверсия, а **глубокая переработка тактики**: из линейного XVII века в тактику XIX века.
Ключевая идея, вокруг которой всё строится:

> XVII век = «выстроились и стояли». XIX век = **расчёт, манёвр, огневая подготовка и огонь по площади.**

Восемь систем, которых в базовой игре нет вообще, — это и есть «масштаб».

Патчи (`patches/`) добавляют новые типы юнитов — механизм подтверждён на `examples/mods/new_unit_test`:
`.prop` в `assets`, регистрация в `units.objects`, членство в расе и производство в `country.script`,

## 3. Система 1: Артиллерия (то, что вы назвали)

Полноценная, а не «стреляет и всё».

**Состав**
- 4 типа орудий: полевая пушка (прямой огонь), гаубица (навесная, по непроходимым), мортира (ближний мин. вылет), скорострелка ( картечь по живой силе)
- 4 типа снарядов: шаровая, фугасная, картечь, шрапнель (airburst)
- Расчёт: угол возвышения, дальность, разброс, задержка подрыва, рикошет

**Цикл выстрела**
1. Игрок выбирает орудие → панель наведения
2. Клиент показывает траекторию и ожидаемое пятно поражения (CEF-оверлей)
3. Клиент шлёт цель на сервер → `net.lua`
4. Server валидирует, списывает снаряды, ставит задержку через `scheduler`
5. `object.setState` переводит орудие в состояние «заряжается» (после моей правки — с валидацией имени)
6. Выстрел: урон по площади через `abilities` (проверяем на F8), либо свой урон, если `abilities.fire` заблокирован
7. Эффекты: дым, вспышка, воронка в земле через `terrain.lower`, тряска камеры
8. Износ ствола → при износе точность падает → ремонт в городе

**Ключевой вопрос (§8,spike):** чем наводить. `orders` сломаны. Варианты:
- (a) свой state в `unit.aix` через патч + `object.setState` — **нужно проверить, патчатся ли `.aix`**
- (b) `abilities.fire` для урона + `world.move` для разворота — работает, но грубо
- (c) после починки C++ — `orders`/`weapon` напрямую, чисто

## 4. Система 2: Доктрина построений

В XIX веке строй решает всё. Уже есть `formation` API.

- **Линия** — максимальный огонь, минимум выживает
- **Колонна** — скорость марша, уязвимость в залпе
- **Каре** — только пехота: отбивает кавалерию, почти не стреляет
- **Клин / рассыпной** — кавалерия
- Автоперестроение по событию: «контратака», «обстрел», «сменить фронт»
- Ошибочный строй даёт штраф урона и морали

---

## 5. Система 3: Мораль и стройность

- Мораль юнита 0–100: падает от потерь, огня рядом, потери командира, обхода
- Состояния: `устойчив` → `колеблюсь` → `паника` → `бегство` → `сплочение`
- В панике юнит не стреляет и разбегается; `attack` без приказа и с `orders` не работает — бегство
  задаётся через `object.setState` на собственные состояния
- Кавалерия в панике наносит урон своим
- Восстановление: за линию, рядом с офицером, вне огня

---

## 6. Система 4: Командная структура

- Офицеры — отдельные юниты: генерал, полковник, капитан
- Аура в радиусе: скорострельность, точность, мораль, скорость передвижения
- Цепочка командования: потерял офицера — теряет бафф; чем выше ранг, тем больше радиус
- Штаб: резервы, пополнение, приказ атаки/обороны/отступления для всей армии
- `vision.radius`, `status`, `attach`, `groups` — всё есть в API

## 9. Риски

| Риск | Что делаем |
|---|---|
| Патчи `.aix` не работают | M0 проверит первым. Фолбэк: наведение через `world.move` + урон через `abilities` |
| `abilities.fire` заблокирован тем же багом C++ | Урон считаем в Lua по площади через `objects.list()` + расстояние. Дороже по CPU, но работает всегда |
| Новые модели невозможны | Юниты получают переименованные и перебалансированные существующие. Прячем честно: «французский мушкетёр» = переработанный мушкетёр, а не новая几何ка |
| Lockstep-десинхрон | `rng.sharedSeed` везде, никаких `pairs()` по изменяемым таблицам, `netrec` на каждом прогоне |
| Объём | Порядок жёсткий: M0→M1→M2. Если M2 не пошла — M3 имеет смысл только с чистым `orders` |
